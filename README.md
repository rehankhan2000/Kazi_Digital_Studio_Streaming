# Zero-Budget P2P Media Streaming Web App

A lightweight, serverless Peer-to-Peer (P2P) web application that enables one user (**Streamer**) to stream a local video or photo file directly to another user (**Viewer**) in real time using **WebRTC**.

The application requires **zero media servers, zero build steps, and zero hosting costs**. All video/photo data flows directly from browser to browser. Lightweight SDP signaling is performed via a free public WebSocket MQTT broker (`wss://broker.emqx.io:8084/mqtt`), and ICE candidates are resolved via Google's free public STUN server (`stun:stun.l.google.com:19302`).

---

## Features

- **Direct P2P Streaming**: Video and image data stream directly between peers using WebRTC. No media server or cloud storage is involved.
- **Zero Cost & Zero Maintenance**: Hosted as static HTML/JS files on GitHub Pages.
- **Video & Photo Support**:
  - Videos (`.mp4`, `.webm`, etc.) stream at 30 fps via HTML5 `<video>` stream capture (`video.captureStream(30)`).
  - Images (`.png`, `.jpg`, etc.) render on a hidden `<canvas>` and stream at 2 fps via canvas capture (`canvas.captureStream(2)`).
- **Password-Derived Room IDs**: Secure, deterministic room matching generated by hashing a user password with SHA-256 (Web Crypto API `crypto.subtle.digest`).
- **Retained Signaling Offers**: Offers published to MQTT use retained messages so viewers receive the live offer even if they open the page after the streamer clicks "Go Live".
- **No External API Keys or Frameworks**: Built using plain HTML5, CSS3, ES6+ JavaScript, and CDN-hosted [MQTT.js](https://unpkg.com/mqtt/dist/mqtt.min.js).

## How It Works (Architecture)

```
+------------------+                    +------------------+
| Streamer Browser |                    |  Viewer Browser  |
+--------+---------+                    +--------+---------+
         |                                       |
         |  1. Generate SHA-256 Room ID from Password |
         +---------------------------------------+
         |                                       |
         |  2. WebRTC SDP Offer                  |
         |----(Publish retained offer to MQTT)--->|
         |    `myapp/<roomId>/streamer`          |
         |                                       |
         |                                       | 3. WebRTC SDP Answer
         |<---(Publish answer to MQTT)-----------|
         |    `myapp/<roomId>/viewer`            |
         |                                       |
         +=======================================+
         |   Direct P2P WebRTC Media Stream      |
         |=======(Media data, NO servers)========>
```

1. **Room ID Hash**: Both Streamer and Viewer enter the same password. The app computes `crypto.subtle.digest('SHA-256', password)` and extracts the first 32 hex characters to form `roomId`.
2. **Signaling over MQTT**:
   - Streamer subscribes to `myapp/<roomId>/viewer` and publishes its WebRTC Offer SDP to `myapp/<roomId>/streamer` with `retain: true`.
   - Viewer subscribes to `myapp/<roomId>/streamer`, reads the retained Offer, generates a WebRTC Answer SDP, and publishes it to `myapp/<roomId>/viewer`.
3. **P2P Media Flow**: Once SDP exchange and STUN candidate gathering complete, WebRTC establishes a direct media pipeline.

## How to Deploy to GitHub Pages

1. **Create a GitHub Repository**:
   - Log into your GitHub account and create a new repository (e.g., `p2p-streaming`).

2. **Upload Project Files**:
   - Push or upload the following files to your repository's `main` or `master` branch:
     - `index.html` (Landing Page)
     - `stream.html` (Streamer Page)
     - `view.html` (Viewer Page)
     - `README.md`

3. **Enable GitHub Pages**:
   - Go to your repository **Settings** tab.
   - On the left sidebar, click **Pages**.
   - Under **Build and deployment** -> **Source**, select **Deploy from a branch**.
   - Set Branch to `main` (or `master`) and directory to `/ (root)`.
   - Click **Save**.

4. **Access Your Live Web App**:
   - After 1–2 minutes, GitHub Pages will deploy your site at:
     - Landing page: `https://<your-username>.github.io/<repo-name>/` (loads `index.html`)
     - Streamer page: `https://<your-username>.github.io/<repo-name>/stream.html`
     - Viewer page: `https://<your-username>.github.io/<repo-name>/view.html`

> **Note on HTTPS**: WebCrypto (`crypto.subtle`) and WebRTC (`RTCPeerConnection`) require a Secure Context (HTTPS or `localhost`). GitHub Pages enforces HTTPS automatically.

## How to Use the App

### Step 1: Streamer ("Go Live")
1. Open `stream.html` in your web browser.
2. Click **Select Video or Photo File** and choose any media file (`.mp4`, `.mov`, `.jpg`, `.png`, etc.).
3. Enter a secret **Room Password** (e.g., `mySecretRoom123`).
4. Click **Go Live**.
5. The local preview will start, and the app will connect to the MQTT broker and publish the retained streaming offer.

### Step 2: Viewer ("Watch Stream")
1. Open `view.html` on another device, browser window, or tab.
2. Enter the **same Room Password** (`mySecretRoom123`).
3. Click **Watch Stream**.
4. The viewer page will connect to the MQTT broker, retrieve the streamer's offer, send a WebRTC answer, and start playing the direct P2P video/photo stream!
